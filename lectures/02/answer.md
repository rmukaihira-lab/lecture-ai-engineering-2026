## 演習

- **使ったモデル・設定（`result.json` の `config` から）**：

  使用モデルは `Qwen/Qwen3.5-0.8B`、学習方法はLoRA（量子化なし）とした。主な設定は、`seed=42`、`num_train_epochs=20`、`warmup_steps=6`、`lr=0.0002`、`lora_r=16`、`lora_alpha=32`、`max_seq_len=512`、`max_new_tokens=96` である。Google ColabのT4 GPUを使用した。

- **自分で学習を実行したか（`executed_training_myself`）**：

  はい（`true`）。Google Colab上で学習データの生成、学習前の評価、LoRAによる追加学習、学習後の評価、未知の質問への評価、結果の保存まで実行した。

- **学習前**：`format_rate` = 0.0952（9.5%） / `content_rate` = 0.0（0%）

- **学習後**：`format_rate` = 1.0（100%） / `content_rate` = 0.9048（90.5%）

- **退行した質問**：

  なし（`regressed = []`）。学習前に正しく回答できていた質問が、学習後に不正解となるケースは確認されなかった。

- **学習後に残った失敗と、その型（根拠なしの質問に断定した / 根拠ありの質問に確認要求で逃げた / 形式の崩れ）**：

  21問中2問で内容の誤りが残った。

  「成績はいつ出ますか」という質問に対し、FAQに記載されていない成績発表日ではなく、課題の提出期限を回答した。また、「オフィスアワーは事前予約が必要ですか」という質問に対しても、予約の要否を確認せず、オフィスアワーの時間を回答した。

  いずれも「根拠なしの質問に断定した」型の失敗である。学習後の形式遵守率は100%であり、形式の崩れは確認されなかった。

- **知識を問う質問（セクション6）の結果（学習前の分類 → 学習後の分類）と気づいたこと**：

  | 質問 | 学習前 | 学習後 |
  |---|---|---|
  | 最終課題の締切 | format_error | asserted |
  | 担当教員の名前 | format_error | needs_review |
  | 次回の講義テーマ | format_error | needs_review |
  | 通常課題の提出期限 | format_error | asserted |

  学習後はすべての質問でJSON形式を守るようになった。

  担当教員の名前や次回の講義テーマについては、FAQに記載がないため確認が必要と判断できた。一方、最終課題の締切については、通常課題の提出期限をそのまま回答しており、異なる情報を混同する問題が見られた。

  この結果から、回答形式を学習できても、質問に対する根拠の有無を常に正しく判断できるとは限らないことが分かった。

- **学習で変わったこと・変わらなかったこと**：

  LoRAによる追加学習により、JSON形式の遵守率は9.5%から100%に、内容正解率は0%から90.5%に改善した。特に、学習前は不足していた `needs_review` の項目を、学習後は適切な形式で出力できるようになった。

  一方、FAQに記載されていない情報について、関連する別の情報を誤って回答するケースは残った。

  形式を正しく出力する能力と、回答内容の正確性は別に評価する必要があると感じた。

## 宿題

- **取り組んだレベル**：基礎

- **変えた設定やデータ**：

  `num_train_epochs` を20から10に変更した。

  学習率 `lr=0.0002`、LoRAランク `lora_r=16`、学習データ14件、検証データ7件、評価用21問など、その他の条件は変更しなかった。

  条件をそろえるため、Google Colabのランタイムを再起動し、学習前の状態から再実行した。

- **結果（比較表や数字）**：

  | 評価項目 | 20エポック | 10エポック |
  |---|---:|---:|
  | 学習前の形式遵守率 | 9.5% | 9.5% |
  | 学習後の形式遵守率 | 100% | 100% |
  | 学習前の内容正解率 | 0% | 0% |
  | 学習後の内容正解率 | 90.5%（19/21問） | 81.0%（17/21問） |
  | 最終Training Loss | 0.013986 | 0.101674 |
  | 学習ステップ数 | 40 | 20 |
  | 学習時間 | 258秒 | 135秒 |

  学習回数を半分にしたところ、学習時間は258秒から135秒へ約48%短縮された。

  学習後の形式遵守率はいずれも100%であり、10エポックでも指定されたJSON形式を守ることができた。

  一方、内容正解率は90.5%から81.0%に低下した。10エポックでは、FAQに記載された提出形式を適切に回答できない例や、根拠のない質問に対して不自然な文章を出力する例が確認された。

  今回の結果では、学習回数を減らすことで処理時間を短縮できたが、回答内容の正確性には一定の影響が生じた。ただし、評価問題は21問と少なく、学習結果にもばらつきがあるため、今回の結果だけで一般的な優劣を断定することはできない。

- **ファインチューニングが向く場面・向かない場面についての考察**：

  ファインチューニングは、JSONなどの出力形式を統一したい場合や、特定の回答方法・文章表現を安定して出力させたい場合に向いていると考える。

  今回の実験でも、少量の学習データを使用したLoRAによって、形式遵守率が大幅に改善したことが確認できた。

  一方、頻繁に更新される情報への対応や、学習データに存在しない事実の確認には、ファインチューニングだけでは不十分だと考える。

  特に実務で利用する場合、回答の形式が正しくても、内容に根拠があるとは限らない。そのため、必要に応じてRAGなどの外部資料を参照する仕組みや、回答の根拠を確認する仕組みを組み合わせることが重要だと考える。
